## 0. 이 앱이 뭔가

자주 나오는 유형의 **문제 푸는 방법을 익히는 앱**.
풀이 순서를 외우게 하는 게 아니라 **조건을 보고 관련 개념이 떠오르게** 만드는 훈련.

아이들이 문제를 못 푸는 진짜 이유는 계산이 아니라, "정삼각형"을 봐도 아무것도 안 떠올라서다.
그 구간만 겨냥한다.

제품 한 문장: **"답을 아는가가 아니라, 다음 한 칸이 떠오르는가."**
→ 기능 판단 기준: **"이게 아이가 다음 개념을 떠올리게 만드나?"**

**말하는 수학과의 관계**
| | 말하는 수학 | 생각 사슬 |
|---|---|---|
| 묻는 것 | 개념을 **설명**할 수 있나 | 조건에서 개념을 **떠올릴** 수 있나 |
| 방식 | 말하기 → AI 채점 | 누르기 → 사슬 잇기 |

### 학습 흐름
```
문제 제시
  → 학생이 문제에서 조건/구하려는 것을 누름
  → 그 단어에서 관련 개념·성질이 3~6개 펼쳐짐
  → 목표와 이어지는 걸 고름
  → 다음 개념이 또 펼쳐짐 (사슬처럼 계속)
  → 식을 세워 답
```
예: 중점 → 닮음 → 닮음비 → 넓이의 비

## 4. 데이터 구조 — 문제는 `PROBLEMS` 배열에만 추가

```js
{
  id:'p2', pick:'탭에 보일 이름', tag:'중2 · 정삼각형',
  sentence:[                                     // key 있는 조각만 눌러짐
    {t:'한 변의 길이가 8cm', kind:'cond', key:'side'},   // cond=조건(노랑)
    {t:'인 '},                                          // key 없으면 그냥 글자
    {t:'넓이', kind:'goal', key:'area'},                // goal=구하는 것(파랑)
    {t:'를 구하시오.'}
  ],
  nodes:{
    eq:{
      label:'정삼각형이다',      // 층 머리
      note:'중립적 안내 한 줄',   // 답을 암시하면 안 됨
      ask:'되묻는 질문',         // note 대신 (간단한 문제용)
      hint:'짧은 힌트',          // 눌러야 나옴. 답 주지 말 것
      items:[
        {t:'넓이 = (√3÷4) × (한 변)²', next:'side'},              // next → 길이 열림
        {t:'세 각이 모두 60°이다', why:'각만으로는 넓이를 못 구해요.'}  // why → 오답
      ]
    },
    end_a:{ end:true, lines:['식1','식2'], ans:'넓이 = 16√3 cm²', cmt:'이 길에 대한 총평' }
  }
}
```

**규칙**
- `next`는 여러 항목이 가질 수 있다 → 그게 갈림길
- 여러 길이 같은 노드로 **합류**해도 된다 (para → sim, lenratio → ratio2)
- `end` 노드는 길마다 여러 개 (길이 다르면 식도 다름)
- 선택지 순서는 화면에서 자동 셔플 → 데이터 순서 신경 쓸 필요 없음

## 5. ★ 문제 고르는 기준

**"어려운 문제"를 고르는 게 아니다.**

| 종류 | 이 앱에 | |
|---|---|---|
| 계산이 어려움 | ✗ | 앱이 계산을 안 하니 무관 |
| **연결이 어려움** | **◎** | **정확히 이 앱의 타겟** |
| 발상이 어려움 | △ | 그 한 수가 선택지에 보여버림 |

**뽑을 것: 풀이가 3단계 이상 이어지는 문제.**
별2개인데 조건 3개에 사슬이 긴 문제 > 별3개인데 공식 하나로 끝나는 문제.

**현장 판별법**: "어디서부터 손대야 할지 모르겠어요" → 최적 / "아, 계산 실수했어요" → 부적합

**적용 범위**: 도형만이 아님. 방정식 활용·함수·확률·수열·미적분 등 **조건이 여럿이고 사슬이 이어지는 문제 전부.**
공식 하나로 끝나는 문제는 *못 만드는 게 아니라 안 만드는 게 나음* (클릭 두 번이면 끝나 앱을 켤 이유가 없음).

## 6. ★★ 오답 만드는 6가지 틀

이 앱에서 제일 어렵고 제일 중요한 작업.
**"말도 안 되는 오답"은 넣지 말 것** — 아무도 안 고르면 선택지가 아니라 자리 채우기다.

| # | 틀 | 예시 |
|---|---|---|
| 1 | **한 단계 빠뜨리기** | 닮음비 1:2까지 구하고 제곱 안 함 |
| 2 | **옆 개념 바꿔치기** | 넓이에 √3÷2 씀(높이 값), 넓이↔둘레 |
| 3 | **조건 하나 무시** | 주어진 조건 중 하나를 안 쓴 결과 |
| 4 | **맞는 말인데 무관** | "세 각이 60°" — 참이지만 넓이로 안 이어짐 |
| 5 | **순서·방향 뒤집기** | 닮음비 1:2를 2:1로 |
| 6 | **차원 혼동** | 길이의 비를 넓이의 비로, 넓이에 세제곱 |

자주 쓰는 구체 실수: ½ 빠뜨리기, 제곱 빠뜨리기, 밑변을 반으로 착각,
"30-60-90이니 빗변의 반이 높이"(그건 밑변), 평행→합동 착각

문제 하나당 이 6개를 훑으며 "이 문제에서 이 실수가 가능한가?"만 확인 → 보통 3~4개가 걸림.

**진짜 자산은 아이들의 실제 오답.** 교재에도 없고 AI도 못 만든다.
→ 수업 중 틀린 게 보이면 한 줄씩 메모. 하루 2~3줄 = 한 달 60개. 이게 진짜 경쟁력.

## 7. ★ 도형은 SVG로 직접 그린다

**교재 이미지 따오기 = 금지.** 도형 그림도 교재 저작물. 문제만 유사문제로 바꾸고 그림은 원본 쓰면
오히려 더 명확한 침해. 상업화를 염두에 두므로 처음부터 깨끗하게.

```html
<svg viewBox="0 0 200 160">
  <polygon points="20,140 180,140 100,20" fill="none" stroke="#14152B" stroke-width="2"/>
  <text x="100" y="155" text-anchor="middle" font-size="12">B</text>
</svg>
```
중등 도형에 필요한 것 전부 가능: 삼각형·사각형·원, 보조선, 각도 호, 변 길이 라벨,
직각기호(□), 같은 길이 빗금(/, //), 평행 표시(▷), 꼭짓점 이름.

**이점**: 파일이 없음(단일 HTML 안에 코드로) / 확대해도 안 깨짐 / "이 변 8→10"이면 숫자 하나만 수정 / 브랜드 색 그대로

**넣는 법**: 문제 카드에 `svg` 필드. 층이 진행되며 보조선이 추가되는 도형은 **노드에도 `svg`** →
단계별로 그림이 바뀜 (이게 되면 학습 효과 큼).

**연결**: 말하는 수학에 이미 도형 생성기 `ddFig`가 있다(`../dodream.html`, v74.4).
여기서 그리다 자주 쓰는 도형이 추려지면 그게 생성기의 기본 목록이 된다.
→ 생성기를 먼저 만들고 도형을 그리는 게 아니라, **도형을 그리다 보면 생성기가 나온다.**

# 14. v0.3 — 조건을 미리 알려주지 않기 + 화면 개편 (2026-09-09, 마스터 지시)

## 14-1. ★ 조건에 미리 색을 칠하지 않는다 (설계 원칙 추가)

**마스터 지적:** 조건과 질문을 미리 노랑·파랑으로 구분해두면 **조건을 찾는 연습이 사라진다.**
지금처럼 짧은 문제는 어차피 누를 게 몇 개 없어 무의미하지만, **문제가 길어지면
"이게 조건인 줄 몰랐던 것"이 많다.** 미리 알려주면 별 생각 없이 누르고 풀게 된다.

→ 2번 표(확정된 결정 사항)에 다음을 추가한 것으로 본다:
| 조건 표시 | **미리 표시하지 않음.** 학생이 찾아 누르면 그때 켜진다 |

**구현**
- `.tk`는 평소 **아무 표시 없음**(색·밑줄 없음). 문장 조각 **전부** 눌러짐
- 맞게 누르면 `.tk.found` → 파란 배경 + 밑줄. "찾았다"는 표시이자 진행 표시
- 조건이 아닌 곳을 누르면 `#toast`에 한 줄: *"여기선 새로 알 수 있는 게 없어요"* (3.4초 후 사라짐)
  - 조각별로 맞춤 문구를 주려면 `sentence` 조각에 `no:'...'`를 달면 된다 (없으면 기본 문구)
- 안내문(`#guide`)은 **남은 단서 개수만** 알려준다. 위치는 안 알려줌
- 새 함수: `renderGuide()` / `tapPiece(i)` / `showToast()` / `hideToast()`

⚠️ **앞으로 문제를 만들 때**: `sentence` 조각을 **의미 단위로** 끊을 것.
조각이 곧 "누를 수 있는 후보"가 되므로, 조건처럼 보이지만 조건이 아닌 조각도
일부러 넣으면 훈련이 된다 (그때 `no:`로 이유를 달아준다).

## 14-2. 화면 개편 — 색 3개로 줄임

**문제였던 것:** 한 화면에 색이 6가지(먹·파랑·초록·분홍·노랑·보라), 박스 스타일이 5가지 섞여 지저분함.
마스터: *"방식은 괜찮고 보여지는 방식이 바뀌었으면"*.

**바꾼 것**
- 색을 **먹(`--ink`) + 파랑(`--blue`) + 회색(`--sub`/`--dim`)** 3개로 통일.
  초록(정답)·분홍(오답)·노랑(힌트)·보라(링크) 전부 제거
  (`--purple/--gold/--sage` 변수는 남겨둠 — 말하는 수학과 합칠 때 대비)
- 층을 **타임라인**으로: `.flow`에 세로 레일 1줄 + 층마다 점(`.hd:before`).
  답한 층은 점이 먹으로 채워짐(`.layer.done`)
- 층 머리를 검은 알약 → **굵은 텍스트 한 줄**(`.from` → `.hd`)
- 선택지 트리 선(`.branch`/`.item:before` 짧은 가로선) 제거 → `.opts`로 단순화
- **고른 선택지 = 먹 배경 흰 글씨** (초록 아님). 화면에서 강조는 이 하나뿐
- 오답 = 배경 살짝 눌린 회색 + 글씨 `--sub` (분홍 아님)
- 힌트/다른 선택지 = 회색 밑줄 텍스트 버튼 (노란 박스 아님). "💡 힌트" → "힌트 보기"
- 도착 카드 = **먹 배경 흰 글씨**. 한 번만 강한 대비 → 도착한 느낌
- 문장 조각 경계 공백 문제: `.tk`에 padding을 주면 조각마다 틈이 벌어짐 →
  padding 대신 `box-shadow:0 0 0 3px` 로 강조 (레이아웃 안 밀림). **다시 padding 주지 말 것**

# 16. v0.5 — 교재 글씨체 + 계산은 직접 입력 + 난이도 (2026-09-09, 마스터 지시)

## 16-1. 교재 글씨체 — 말하는 수학의 `mfmt()`를 그대로 가져옴

`dodream.html`의 **v75.1 `mfmt()`**(수식을 교재처럼 보이게 하는 표시 전용 변환기)를
`chain/index.html`에 **복사**해 넣었다. dodream.html은 건드리지 않음(격리).
- 서체: `"STIX Two Text","Noto Serif KR",Georgia,"Times New Roman",serif` (`.mf`)
- CSS 클래스 `.mf / .mf-v / .mf-frac / .mf-num / .mf-den / .mf-rad / .mf-rcd / .mf-sup / .mf-sub` 도 같이 복사
- **그리는 모든 곳에 적용**: 문장 조각·층 머리·ask·note·선택지·오답 설명·힌트·식·답·총평·생각의 길 칩
- ⚠️ mfmt는 **표시 전용**이다. 원본 데이터를 바꾸지 않는다. 입력칸·정답 비교에는 쓰지 말 것
- 검증: 6문제의 문자열 422개를 mfmt에 통과시켜 `textContent`가 **원본과 한 글자도 다르지 않음**을 확인
- 알려진 점: 단위 `cm`도 변수로 보고 기울임이 된다. 말하는 수학과 **같은 동작**이라 그대로 둠

## 16-2. ★ 계산은 선택지로 주지 말고 직접 입력 (구조 변경)

**마스터 지적:** *"넓이 식이 선택됐는데 거기에 숫자 넣은 걸 또 질문처럼 해버리면 너무 쉽다.
그냥 답이 뭔지 물었어야지. 그래야 고른 식에 맞춰서 계산해서 답을 찾지."*

→ 노드에 `solve`가 있으면 **선택지 대신 입력칸**이 나온다.

```js
area:{ label:'직각삼각형이다',
  solve:{ q:'△ABC의 넓이는 몇 cm²일까요?', unit:'cm²', accept:['24'],
          wrong:'직각을 끼고 있는 두 변이 밑변과 높이예요. 삼각형이니 ½도 잊지 말고요.',
          say:'맞아요. 넓이가 24cm²예요.',   // 생략하면 입력값을 되읽어 줌
          ph:'숫자만' },                      // placeholder (생략 가능)
  hint:'직각을 낀 두 변은 6cm와 8cm.',
  next:'area 다음 노드' }
```
- `numOnly()`로 숫자만 뽑아 비교 → `2`, `2cm`, `r=2` 다 통과
- 틀리면 **답을 주지 않고** `wrong` 문구로 방향만. 시도 횟수는 `solveTries`에 쌓여 도착 카드에 표시
  (*"힌트 없이 끝까지 갔어요. · 계산 고쳐 넣기 2번"*)
- Enter로도 제출됨
- 관련 함수: `solveHTML(node)` / `bindSolve(key, layer)` / `numOnly(v)`
- ⚠️ `solve` 노드에는 `items`를 같이 두지 말 것. `next`는 필수

**적용:** t01 2곳(밑각 72°, ∠DBC 36°) · t02 3곳(넓이 24, r=2 두 경로) · q01 1곳(EC 4cm)

## 16-3. ★ 난이도 — "고를 게 너무 정해져 있다"

**마스터 지적:** *"난이도가 좀 있는 문젠데 보기를 보면 어떤 걸 선택해야 할지가 너무 정해져 있는 느낌."*

원인 3개를 찾아 고쳤다. **앞으로 문제 만들 때 이 3개를 매번 점검할 것.**

| 원인 | 고친 방법 |
|---|---|
| `note`/`ask`가 답을 암시했다 | 중립으로. "직각을 알았으니 넓이를 바로 구할 수 있어요"(답 지목) → "이 세 숫자에서 알아낼 수 있는 것이 있어요" |
| **정답에만 괄호 설명**이 붙어 있었다 → 그게 정답 표시가 됨 | "∠BDC = ∠BCD (BD와 BC가 각각 마주보는 각)" → "∠BDC = ∠BCD 이다". 오답도 같은 길이·같은 꼴로 |
| 오답이 너무 허술했다 (아무도 안 고를 것) | 실제로 자주 하는 실수로 교체. 예: "세 변의 길이가 모두 같다"(허술) → "한 밑각의 크기는 꼭지각의 절반이다", "가장 긴 변이 10cm이므로 둔각삼각형이다", "내심에서 꼭짓점까지의 거리가 반지름이다"(외심 혼동), "△ABE와 △ADE가 합동이다" |

## 16-4. 값이 우연히 맞는 오답은 넣지 않는다

**마스터 지시:** *"헷갈릴 여지가 없게 하는 게 좋겠어."*
→ 미결이던 질문(q01의 `AD에서 AB를 그냥 뺀다 (10−6=4)`)은 **선택지에서 삭제**.
t01의 `∠A와 크기가 같다`(답이 실제로 36°)도 같은 이유로 삭제.

**규칙:** 답과 같은 값이 나오는 오답은 만들지 않는다. 아이가 억울하고, 맞았는지 틀렸는지 헷갈린다.
