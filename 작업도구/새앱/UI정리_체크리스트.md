# UI 정리 체크리스트 (마스터 2026-10-14 지시 · 대전제 3번)

> 마스터: "한 화면에 엄청난 설명들이 보여 굉장히 복잡해 보인다. 자세한 설명은 처음부터 보여 주지 말고 그 단어를 누르거나 버튼으로 그 페이지에 들어갔을 때 보이게.
> 로그인했을 때 화면도 너무 복잡하다 — 메인 개념 질문을 빼고는 다른 페이지로 보내면 좋겠다.
> 현재까지 만들어진 앱의 기능을 하나하나 점검하고 부적합한 것은 바로 고쳐라. 한도가 풀리면 지시 없이 바로 이어서."

**이어서 하는 법(새 창·한도 풀린 뒤):** 이 파일에서 ☐ 인 것을 위에서부터 한다. 끝낸 것은 ☑ 로 바꾸고 무엇을 바꿨는지 한 줄 적는다.
고칠 때마다 `app/js/core.js` 의 `A.VERSION` 과 `index.html`·`teacher.html` 의 `?v=` 를 올리고, 브라우저에서 `new Function(본문)` 문법 검사 → `app/_test.html`(가짜 학생) 로 화면 확인 → 375px 넘침 확인 → 커밋 → `git push origin main`(이 PC는 10/14 에 GitHub 승인해 둠).
다 끝나면 CronList 로 「UI 정리 이어서」 예약을 지우고 마스터에게 다섯 칸 보고.

## 기준 (대전제 3번)
- 한 화면에 **지금 할 일 하나**가 크게. 나머지는 작은 버튼 → 다른 화면.
- 설명 문장은 기본으로 숨김 — 낱말 누르면 설명 창(`data-term` + TERMS) 또는 「?」/「자세히」 버튼.
- 화면 위 부제(sub)는 한 줄 이내, 없어도 되면 뺀다.
