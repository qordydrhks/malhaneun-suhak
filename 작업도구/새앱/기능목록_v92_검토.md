# 기능목록 v92 검토 정리

- 작성일: 2026-10-03
- 목적: 현재 앱은 보존하고, 새 학생 앱을 별도 구조로 만들 때 기능 범위와 개발 원칙을 정리한다.
- 검토 대상: 마스터가 제공한 `기능목록_v92.pdf` 43개 항목
- 관련 원본: `기능목록_v92.html`, `기능목록.py`

## 1. 결론

기능목록의 방향은 맞다. 특히 질문 목록을 없애고, 친구가 질문을 하나씩 내며, 학생이 한 화면에서 문제에 집중하게 만드는 방향이 좋다.

다만 현재 분류를 그대로 개발 범위로 사용하면 `꼭 22개 + 바꿈 7개`, 총 29개가 첫 버전에 들어간다. 또한 새로 만들 기능과 기존 앱에서 계속 사용할 기능이 모두 `꼭`으로 표시되어 있다. 이 상태로 개발하면 새 앱도 다시 복잡해질 가능성이 크다.

새 앱의 첫 목표는 43개 기능을 옮기는 것이 아니라 다음 학습 한 바퀴를 완성하는 것이다.

> 친구의 질문 → 학생이 말함 → 핵심 이해 확인 → 필요한 도움 → 다시 설명 → 결과와 모범 답 → 다음 질문

## 2. 현재 앱과 새 앱의 관계

- 현재 앱은 삭제하거나 덮어쓰지 않는다.
- 현재 앱은 기능·데이터·운영 방식의 참고 자료이자 비상 복귀 버전으로 둔다.
- 새 앱은 별도 파일/폴더에서 시작한다.
- 검증된 문제 데이터, 수식 표시, 그림, Supabase 기록, AI 서버 중계는 가능한 범위에서 재사용한다.
- 현재 앱의 복잡한 화면 구조와 이벤트 연결은 그대로 복사하지 않는다.
- 학생 앱을 먼저 만들고, 그동안 선생님·학부모 화면은 현재 앱을 사용한다.
- 새 학생 앱이 남긴 기록을 현재 선생님·학부모 화면이 읽을 수 있도록 데이터 호환을 먼저 정한다.

## 3. 기능 분류를 바꾸는 이유

기존 `꼭 / 바꿈 / 나중에 / 버림`만으로는 구현 범위를 정확히 알기 어렵다. 앞으로는 아래 다섯 가지로 나누는 것이 좋다.

| 새 분류 | 뜻 |
|---|---|
| 새로 구현 | 새 학생 앱에 직접 만드는 기능 |
| 기존 앱 사용 | 새로 만들지 않고 현재 선생님·학부모 화면을 계속 사용 |
| 연동 필수 | 화면은 기존 것을 쓰더라도 새 앱의 데이터와 반드시 연결되어야 함 |
| 후속 개발 | 핵심 학습 흐름을 검증한 뒤 추가 |
| 제외 | 새 앱에 옮기지 않음 |

`꼭`은 "새로 구현"과 같은 뜻이 아니다. 예를 들어 선생님 대시보드는 운영상 꼭 필요하지만, 새 학생 앱 첫 판에서 다시 만들 필요는 없다.

## 4. 새 학생 앱 첫 판에 새로 구현할 것

첫 판은 초4-2의 대표 소단원 하나를 실제 데이터와 실제 AI 흐름으로 끝까지 사용할 수 있는 수준으로 만든다. 화면만 있는 가짜 기능은 만들지 않는다.

1. 로그인과 자동 로그인
2. 학원 기기 등록 확인
3. 과정 전환과 오늘의 미션 진입
4. 한 화면에 질문 하나만 제시
5. 말하기와 글 입력 대안
6. 핵심 아이디어 기반 채점
7. 되묻기 → 짧은 설명 → 다시 묻기 흐름
8. 통과 후 모범 답과 `짚은 핵심 ✓` 표시
9. 1·2·3회차 진행
10. 스테이지 마지막 기본문제
11. 진행 상태 저장과 이어하기
12. 도움 필요 기록
13. 숫자 친구들의 상황별 반응과 깜빡임
14. 교재와 같은 수식 표시와 필요한 문제 그림

초기 화면 검증에서는 우주 지도·상점·코인보다 위 학습 흐름을 먼저 완성한다. 게임 요소는 학습 흐름이 정상적으로 작동한 뒤 붙여도 된다.

## 5. 한 학습 엔진으로 합칠 것

기능목록의 아래 항목은 별도 기능으로 각각 만들지 않는다.

- AI 채점
- 힌트 3단계
- 질문 계단
- 회차 1·2·3
- 틀린 질문 그날 잠금
- 도움 필요 알림

이 항목들은 하나의 상태 흐름으로 관리한다.

```text
질문 제시
  → 답변 받기
  → 핵심 아이디어 판정
      → 충족: 통과 결과 + 모범 답
      → 일부 부족: 빠진 핵심 되묻기
      → 계속 막힘: 짧게 가르치기
      → 다시 질문
      → 정해진 횟수만큼 막힘: 도움 필요 기록 + 당일 평가 종료
```

화면은 학생에게 현재 필요한 한 단계만 보여 준다. 내부 상태나 점수 계산을 한 화면에 모두 노출하지 않는다.

## 6. 통과 기준과 이해 등급 점수는 분리한다

두 값을 섞으면 안 된다.

### 질문 통과 기준

- 해당 질문의 핵심 아이디어 2~3개를 이해했는지로 판정한다.
- 화면에 70점 같은 숫자 합격선을 보여 주지 않는다.
- `70점을 못 넘으면 잠금`이라는 표현은 새 앱 명세에서 `핵심을 충족하지 못한 질문은 당일 평가 종료`로 바꾸는 것이 좋다.

### 장기 이해 등급

- 마스터가 결정한 루나 → 테라 → 솔 → 갤럭시 → 코스모스 등급에 사용한다.
- 처음 통과한 품질, 힌트 사용, 다음 날 통과, 회차 깊이 등을 내부에서 누적한다.
- 아이에게는 원점수보다 등급과 이해하기 쉬운 설명을 보여 준다.
- 다시 연습해도 처음 통과 품질 기록은 덮어쓰지 않는다.
- 어른 화면에서는 판단 근거가 되는 상세 내역을 볼 수 있어야 한다.

## 7. 문제 화면 원칙

문제를 푸는 화면에서는 게임 지도, 통계, 상점, 여러 메뉴를 함께 보여 주지 않는다.

- 상단: 짧은 진행 상태와 나가기
- 중앙: 지금 답할 질문 하나
- 하단: 지금 사용할 핵심 행동 하나(말하기 또는 답 제출)
- 옆/하단 보조: 숫자 친구의 반응과 필요한 힌트
- 결과: 짚은 핵심, 짧은 피드백, 모범 답, 다음 버튼

게임 요소는 문제 전후의 진행감과 보상에 사용한다. 학습 중에는 문제를 읽고 생각하고 말하는 데 집중하게 한다.

## 8. 게임 용어는 한 체계로 통일한다

행성·스테이지·별·별자리·지도를 동시에 쓰면 구조가 헷갈릴 수 있다. 최종 디자인 전에 용어를 한 번 확정한다.

예시:

- 대단원: 별자리
- 소단원: 별
- 한 번의 학습: 미션
- 복습할 내용: 다시 빛나야 할 별
- 학습 기록: 완성한 별자리
- 숫자 친구들: 함께 이동하는 동료

이 예시는 확정안이 아니다. 중요한 것은 같은 대상을 화면마다 다른 말로 부르지 않는 것이다.

## 9. 기존 앱을 그대로 사용할 것

다음은 새 학생 앱 첫 판에서 다시 만들지 않는다.

- 선생님 PIN 로그인과 원장/선생님 권한
- 학습 현황 대시보드
- 학생 등록·수정·학습 이력
- 회차 열기
- AI 연결과 비용 보기
- 관리자 비밀번호 변경
- 현재 학부모 리포트

다만 새 앱의 기록이 위 화면에 정확히 나타나는지는 반드시 회귀 테스트한다.

## 10. 첫 판 뒤로 미룰 것

- 제한 시간 타이머
- 개념 다시 보기·학습 공간
- 채점 이의 제기
- 응용 문제 도전
- 선생님 배정 문제
- 별자리 형태의 상세 학습 기록 화면
- 문제은행
- 문제 미리 만들기
- 다른 학년의 옛 방식 질문 이전
- 개념카드 879개 이전
- 보상 경제·상점·꾸미기 전체 구현
- 연산·암산 및 용어 맞히기 별도 공간

7일 복습은 핵심 화면이 검증된 다음 운영 시험 단계에서 붙인다. 처음부터 화면에 넣을 필요는 없지만, 저장 구조에는 복습 예정일을 확장할 수 있게 둔다.

## 11. 제외할 것

기능목록의 제안대로 아래 기능은 새 앱에서 제외한다.

- 학생이 질문 목록에서 직접 질문을 고르는 화면
- 별도 개념 채팅
- AI가 만드는 빈칸 채워보기
- 옛 질문 더미를 배정하는 화면
- 앱 안 개념·질문 편집기

질문과 힌트는 설계 파일과 검토 PDF를 정본으로 관리한다.

## 12. 개발 전에 반드시 결정할 것

1. **상태 흐름:** 질문·되묻기·설명·재질문·통과·막힘의 정확한 전환 조건
2. **기록 호환:** 새 앱이 현재 Supabase의 어떤 표와 필드를 그대로 쓸지
3. **이어하기:** 학습 도중 나가거나 앱이 꺼졌을 때 어느 단계부터 복구할지
4. **AI 실패:** 지연·오류·서버 중단 때 가짜 통과 기록을 남기지 않는 처리
5. **마이크 대안:** 권한 거부·인식 실패 때 글 입력으로 자연스럽게 전환
6. **당일 잠금:** 잠금 대상, 다음 날 해제 시각, 선생님 수동 해제 여부
7. **모범 답 공개:** 통과 시와 여러 번 막힌 뒤 각각 무엇을 보여 줄지
8. **학부모 링크 보안:** 토큰 방식과 기존 링크 이전 방법
9. **음성 개인정보:** 원음 저장 여부와 변환된 글의 보관 범위
10. **게임 용어:** 지도·등급·별·미션의 최종 명칭

## 13. 권장 개발 순서

1. 새 앱 전용 폴더와 실행 파일을 만들고 현재 앱과 분리한다.
2. 현재 기록 표를 분석해 새 앱의 최소 데이터 계약을 정한다.
3. 초4-2 대표 소단원 하나로 질문 상태 흐름을 만든다.
4. 모바일 한 화면에서 질문 → 말하기 → 피드백 → 다음 질문을 실제로 시험한다.
5. 선생님 대시보드와 학부모 리포트에 새 기록이 제대로 보이는지 확인한다.
6. 사용성이 확인되면 지도, 7일 복습, 등급과 보상을 차례로 추가한다.
7. 다른 학년은 새 질문 방식으로 설계된 뒤 옮긴다.

## 14. 첫 판 완료 기준

- 학생이 로그인 후 무엇을 해야 하는지 설명 없이 알 수 있다.
- 문제 화면에서 주 행동이 하나만 보인다.
- 말하기와 글 입력이 모두 실제로 작동한다.
- AI가 실패해도 가짜 점수나 통과 기록이 생기지 않는다.
- 통과·부분 부족·계속 막힘이 서로 다른 기록으로 남는다.
- 통과한 학생은 모범 답과 자신이 짚은 핵심을 확인한다.
- 나갔다 돌아와도 학습 상태가 이어진다.
- 현재 선생님 화면에서 새 기록과 도움 필요 학생을 확인할 수 있다.
- 현재 학부모 리포트가 새 기록을 잘못 해석하지 않는다.
- 모바일에서 키보드·마이크·스크롤·터치가 충돌하지 않는다.
- 콘솔 오류가 없다.

## 15. 이미 확정된 마스터 결정과의 관계

이 문서는 아래 결정을 바꾸지 않는다.

- 현재 앱은 참고용으로 보존하고 새 앱을 별도로 만든다.
- 로그인과 학원 기기 등록은 유지한다.
- 학생이 질문 목록에서 고르는 방식은 없앤다.
- 여러 과정을 공부하는 학생은 과정별 지도를 두고 전환할 수 있게 한다.
- 나의 기록에서 숫자를 누르면 해당 질문 목록을 볼 수 있게 한다.
- 통과한 질문만 모범 답을 볼 수 있다.
- 당일 평가에서 막힌 질문은 다음 날 다시 열린다.
- 다시 연습해도 처음 통과 품질은 이해 등급 계산의 기준으로 유지한다.
- 등급은 학기마다 새로 시작하고 지난 학기는 배지·메달로 남긴다.
- 등급 이름은 루나 → 테라 → 솔 → 갤럭시 → 코스모스다.
- 아이에게 숫자 계산식을 계속 보여 주지 않고, 궁금할 때 눌러 설명을 본다.

세부 점수식, 등급 경계, 상점 경제, 연산·용어 게임은 아직 별도 확정이 필요한 항목으로 본다.
