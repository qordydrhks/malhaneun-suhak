# 개념카드(DD_CARDS · DD_KEYPOINTS) 만들기 — 작업 도구

새 학년의 **개념카드**를 만들 때 쓰는 것들. (유형별 질문은 `../유형질문/` 쪽이다.)
**여기 있는 걸 고쳐서 쓰고, 새로 만들지 마라.**

절차 본체는 저장소 `CLAUDE.md`의 **7-B절(중3)·7-C절(고1-1)** 에 있다. 먼저 읽어라.

## 파일

| 파일 | 무엇 |
|---|---|
| `GUIDE_CARD_H11.md` | **에이전트에게 읽히는 작성 지침.** 고1-1용이지만 다른 학년도 이걸 고쳐 쓴다 |
| `prep_h11.py` | 교재 차례 → 소단원 목록 + 본문 쪽 렌더(PNG). **쪽수 매핑표가 여기 있다** |
| `check_h11.py` | 기계 점검(개수·이름 일치·질문 기호·보기 중복·표기 위반·범위 밖 용어·그림 참조) |
| `dump_h11.py` | 사람이 전수로 읽기 좋게 카드를 텍스트로 뽑는다 |
| `build_h11.py` | dodream.html에 넣을 블록 만들기 + 삽입 (**옛 질문이 없는 학년**용) |
| `build_m32.py` | 같은 일. **옛 질문(legacy)이 있어서 글자 그대로 옮겨야 하는 학년**용 |

## 순서

1. `prep_h11.py` 로 차례를 옮겨 적고 소단원 목록을 만든 뒤 본문 쪽을 PNG로 렌더한다
2. 조각(중단원 몇 개씩)마다 Sonnet 에이전트 하나 — `GUIDE_CARD_*.md`를 **전부 읽히고** 시작.
   프롬프트에 **"결과 파일을 먼저 저장하고 나서 자기 점검하라"** 를 반드시 박을 것
   (한도 429로 죽어도 결과가 남는다). **한 번에 3~4개만** 띄운다
3. `check_h11.py` 로 기계 점검 → 걸린 것 수정
4. **내가 전 문항을 직접 읽는다** (`dump_h11.py`). 기계가 못 잡는 것은 아래 참고
5. `build_*.py` (미리보기) → 마스터 승인 → `--apply`
6. 브라우저로 실제 렌더 확인 → `APP_VERSION` 올리고 커밋

## 🚨 반드시 지킬 것

- **교재 쪽수는 파일명·오프셋을 믿지 말고 인쇄된 쪽번호로 확인.**
  고1-1 교재는 파일1에 인쇄 91·92쪽이 **두 번** 들어 있어 93쪽부터 2쪽씩 밀렸다.
- **대단원 이름은 번호식**(`1. 다항식`). 로마숫자(`Ⅰ.`)를 쓰면 편집기 `ceNum()`이 0을 내서
  코드가 전부 겹친다.
- **소단원 번호는 대단원이 바뀌어도 01부터 다시 세지 말고 이어 붙인다**(01~91).
  편집기 코드가 `접두사+대단원번호+소단원번호`라서, 이어 붙여야 코드가 고유해진다.
- **늦게 추가한 학년은** `GRADES`에 항목을 먼저 넣고 `ddApplyLateGrade(id, baseId)`를 부른다.
  GRADES에 없으면 조용히 아무것도 안 한다. 쓴 baseId: 91~98만번대.
- **dodream.html은 CRLF로 써라** — `io.open(p,'w',encoding='utf-8',newline='\r\n')`.
  `newline=''`을 주면 파일 전체가 LF가 되고 `git diff`에는 안 보인다.

## 기계가 못 잡는 것 — 사람이 읽어야 한다

- 기본문제 **정답 번호가 해설과 어긋난 것**, 계산 오류 (전부 검산할 것)
- **거짓 전제가 깔린 문제** (중3 "이렇게 묶으면 안 된다"고 했는데 실제로는 됐다)
- **조건이 빠져 답이 안 나오는 문제** (중3 원 문제에서 세 점이 일직선이라는 조건 누락)
- **힌트가 정답을 그대로 말하는 것** (중3 "산포도"의 한자 풀이가 곧 답이었다)
- **설명이 사실과 다른 것** (고1-1 "행은 위에서 아래로 가는 가로줄")
- **low와 high가 같은 질문** — `"~는 어떻게 구할까?"` / `"~를 구하는 방법을 설명해 봐."`
  꼬리말(설명해 봐/말해 줘/어떻게/방법을/과정을)을 불용어로 지우고 비교해야 걸린다
- **해설이 보기를 `①②③④`로 가리키는 것** — 보기 버튼에는 번호가 안 붙는다
- **표시기(mfmt)가 깨뜨리는 표기** — 브라우저에서 실제로 그려 봐야 안다.
  `nPr/r!` → 잘못된 분수. 데이터에 괄호를 씌워라(`nPr/(r!)`). 앱 코드는 건드리지 말 것
- **문자 겹침** (`ax²+bx+c`의 a·b·c를 인수 자리에 또 쓰기)
- `너가` → `네가`, 유니코드 위첨자 `⁴ ⁿ`, 유니코드 분수 `½`
