# 유형별 말하기 질문(DD_QSET) 작성 지침 — 초5·초6

## 이 앱이 뭘 하나

"말하는 수학" — 초등학생이 수학 개념을 **자기 말로 설명**하면 AI가 듣고 채점한다.
제품 한 문장: **"풀 수 있는가가 아니라, 설명할 수 있는가."**
그래서 질문은 "계산해 봐"가 아니라 **"설명해 봐 / 왜 그런지 말해 봐"** 여야 한다.

## 왜 유형별 질문이 필요한가

기존 질문은 대부분 "~이란 무엇일까?"(회상)라서 **외운 아이와 이해한 아이가 똑같은 답**을 했다.
그래서 질문을 5유형으로 갈라 기억/이해를 구분한다.

| type | 무엇을 보나 | 층 |
|---|---|---|
| `recall` 회상 | 정의·공식을 정확히 꺼내는가 | 기억 |
| `reason` 이유 | 왜 그렇게 되는지 설명하는가 | 이해 |
| `example` 예 만들기 | 스스로 예를 만들어 내는가 | 이해 |
| `condition` 조건 | 언제 되고 언제 안 되는가 | 이해 |
| `error` 오류 찾기 | 틀린 것을 짚고 고치는가 | 이해 |

`example`·`error`가 특히 중요하다 — **암기만으로는 통과가 안 된다.**

## ⚠️ 가장 중요한 규칙 (지난번 초4 300문항 점검에서 나온 교훈)

**다섯 유형은 필수가 아니라 선택이다. 개념당 3~5개면 충분하다.**
억지로 다섯 칸을 채우면 아래 셋이 반드시 생긴다. 초4에서 억지 12개·중복 21개가 나와 21개를 지웠다.

버릴 질문을 거르는 **판단 기준 두 개**:

1. **약속 질문** — 학생이 "그냥 그렇게 약속한 거예요"라고 답하면 그게 정답인가?
   → 그렇다면 **버려라.** (예: "왜 분수의 위를 분자라고 부를까?" → 그냥 그렇게 부르기로 한 것)
2. **중복 질문** — 그 답이 같은 개념의 다른 질문 답과 사실상 같은가?
   → 같으면 **버려라.** (recall과 reason의 답이 같은 말이 되는 경우가 가장 흔하다)

여기에 하나 더:

3. **순환 질문 금지** — 질문 문장 안에 이미 답이 들어 있으면 안 된다.
   (나쁨: "평행한 두 변이 있는 사각형을 사다리꼴이라고 하는데, 사다리꼴이 뭘까?")

`condition` 유형은 **조건이 실제로 있는 개념에만** 쓴다.
(초4에서도 60개 중 40개만 썼다. "언제 되고 언제 안 되는가"가 없는 개념엔 넣지 마라.)

## 출력 형식

**JSON 배열** 하나. 개념 순서는 입력 파일 순서 그대로. 개념 하나당 객체 하나:

```json
{
  "big": "입력 파일의 big 값 그대로",
  "small": "입력 파일의 small 값 그대로",
  "memory": ["정의·공식처럼 정확히 꺼내야 하는 것 (2개 내외)"],
  "understand": ["왜 그런지 / 어떤 조건인지 (2개 내외)"],
  "misconceptions": ["아이들이 실제로 하는 틀린 행동 (2~4개)"],
  "questions": [
    {"type": "recall", "q": "질문 한 문장", "answerHint": "기대 답 핵심"},
    {"type": "error", "q": "질문", "answerHint": "기대 답 핵심", "basedOn": "misconceptions 중 하나와 글자까지 똑같이"}
  ]
}
```

- `big`/`small`은 **한 글자도 바꾸지 마라.** 앱이 이 글자로 개념을 찾는다.
- `memory` / `understand` 는 **채점 기준**이다. AI 채점기가 이 문장을 그대로 기준 삼는다.
  → **사실이 틀리면 학생이 맞는 답을 하고도 틀렸다고 채점된다.** 반드시 정확하게.
- `misconceptions` 는 오답의 **이름표**다. "같은 오해 3회" 같은 집계에 쓰이므로
  짧고 구체적인 행동 묘사로 쓴다. ("헷갈려한다" X → "분모끼리도 더해 버린다" O)
- `error` 유형에는 `basedOn` 을 **반드시** 넣고, `misconceptions` 배열의 한 문자열과
  **글자까지 똑같이** 맞춘다.

## 말투·수준

- 뚜삐(친구 같은 AI 캐릭터)가 초등학생에게 **반말**로 묻는다: "~일까?", "~말해 봐.", "~설명해 봐."
- 질문은 **한 문장**(길어야 두 문장). 초등학생이 소리 내어 답할 수 있어야 한다.
- 그 학년이 아직 안 배운 용어를 쓰지 마라. (초5·초6 교육과정 밖 용어 금지: 무리수, 함수, 미지수 x 등)
- `answerHint` 는 채점 AI가 볼 **기대 답의 핵심** 1~2문장. 학생 말투로 쓸 필요 없다.
- **`answerHint` 안의 계산·수는 반드시 직접 검산할 것.** 여기 숫자가 틀리면 채점이 통째로 망가진다.

## 수식 표기 규칙 (반드시 지켜)

- LaTeX 금지. 역슬래시(\) 한 개도 쓰지 마.
- 분수는 슬래시 하나로: `1/2`, `(a+b)/2`. 대분수는 `1과 2/3` 처럼 한글로.
- 거듭제곱은 `x²`, `x³` 그대로. 기호는 유니코드 그대로: `× ÷ ≤ ≥ ≠ ° π ㎠ ㎤ ∠ ∥ ⊥`
- 곱셈은 `×`(별표 금지). 마크다운(`**굵게**`, `$수식$`) 금지.

## 입력 파일

각 개념마다 이런 정보가 들어 있다:

- `concept` — 학생에게 보여주는 개념 설명(앱에 이미 있는 것)
- `keyPoints` — 기존 핵심 채점 포인트
- `basicProblem` — 기본문제 지문
- `existingQuestions` — **이미 앱에 있는 말하기 질문**.
  → 새 질문이 이것과 **같은 답을 요구하면 안 된다.** 특히 `recall`이 겹치기 쉽다.
  겹칠 것 같으면 각도를 바꾸거나 그 유형을 빼라.

## 제출 전 자기 점검 (반드시)

1. 개념마다 질문 3~5개인가? 억지로 5개 채운 것은 없는가?
2. 모든 질문을 판단 기준 1(약속)·2(중복)·3(순환)으로 다시 훑었는가?
3. `existingQuestions`와 답이 같은 질문은 없는가?
4. `error` 질문마다 `basedOn`이 `misconceptions`의 문자열과 정확히 일치하는가?
5. `answerHint`의 수·계산을 전부 검산했는가?
6. `memory`/`understand` 문장이 교육과정 사실로 정확한가?
7. JSON이 유효한가? `big`/`small`이 입력과 글자까지 같은가?
