# 말하는 수학 숫자 캐릭터 바이블

이 문서는 말하는 수학의 숫자 캐릭터를 앱에 구현할 때 기준으로 삼는 디자인 설정집이다. 캐릭터 관련 시안, 일러스트, UI 배치, 애니메이션을 만들기 전에 먼저 이 문서를 확인한다.

> 현재 상태: **앱 1차 연결 끝 + 깜빡임 프레임 30장 준비 + 리깅 파츠 1차 제작 (2026-10-01)** — 폴라 질문 상태에서 깜빡임을 시험 연결했고, 나머지 감은 눈 프레임은 앱 연결 대기 중이다(10절).
>
> 이름과 핵심 콘셉트는 확정되었다. 마스터가 2026-10-01 "지금 앱에 적용하자"고 결정해, 부품 분리를 기다리지 않고 **표정 그림을 통째로 바꿔 끼우는 방식**으로 먼저 넣었다. 눈·입·팔다리를 나눈 리깅용 1차 자산은 만들었으며, 앱 연결과 피벗 보정은 2차 작업이다(10절).

## 3. 공통 미술 방향

### 대상과 인상

- 핵심 대상은 초등학교 4~6학년이다. 친근하고 귀여우면서도 유아용 장난감처럼 보이지 않아야 한다.
- 숫자 자체가 몸이다. 통통하고 편안한 숫자 실루엣을 유지하며, 네모 블록을 쌓아 숫자를 만드는 구조는 사용하지 않는다.
- 재질은 진주광과 유리 젤리를 섞은 듯 맑고 반짝이게 표현한다. 밝은 면, 중간 면, 어두운 면이 분명해 작은 화면에서도 입체감이 읽혀야 한다.
- 눈은 크되 캐릭터마다 눈매와 시선의 성격이 달라야 한다. 표정은 눈동자 색 변경만으로 만들지 않는다.
- 얼굴, 손발, 장신구를 더해도 숫자 윤곽이 먼저 읽혀야 한다. 장신구가 숫자 모양을 가리거나 다른 숫자로 보이게 해서는 안 된다.
- 0·1·7·8은 머리 위에 자기 숫자가 작게 떠 있다. 2는 떠 있는 숫자 대신 노란 병아리 뚜삐가 머리 위에 앉는다.

### 표정 원칙

- 각 감정은 눈 모양, 눈꺼풀, 동공 방향과 크기, 눈썹, 입, 고개 각도, 손, 몸의 기울기와 무게 중심을 함께 바꿔 한눈에 구분한다.
- 물음표, 느낌표, 반짝임, 생각 점 같은 기호는 표정을 보조할 뿐 감정을 대신하지 않는다.
- 캐릭터의 성격은 유지하되 같은 상황의 의미는 다섯 캐릭터에서 일관되게 읽혀야 한다.
- 오답 표정은 학생을 비난하거나 실망시키는 얼굴이 아니다. 아쉬움은 짧게 보이고 곧 다시 도전할 수 있는 자세로 이어진다.

### 움직임 원칙

- 정지 이미지뿐 아니라 눈 깜빡임, 잔잔한 리듬, 손짓, 듣기·생각·풀이·칭찬 제스처를 각각 분리할 수 있는 구조로 제작한다.
- 학습 중 계속 튀거나 흔들리지 않는다. 움직임은 상태가 바뀌거나 학생에게 의미 있는 반응을 줄 때만 사용한다.
- 눈 깜빡임과 호흡 같은 기본 움직임은 느리고 작게, 칭찬이나 아하 반응은 짧고 명확하게 만든다.
- 모션 감소 설정에서는 애니메이션 대신 같은 뜻의 정지 포즈로 바꾼다. 움직임만으로 상태를 전달하지 않는다.
- 학부모 보고서에는 아이가 선택한 캐릭터의 **뿌듯한 정지 모습**을 사용한다.

## 4. 공통 표정 8종과 앱 상황

표정 시트는 **왼쪽에서 오른쪽, 위 행에서 아래 행** 순서로 1~8을 읽는다.

| 번호 | 표정·상황 | 앱에서 쓰는 때 | 반드시 보여야 할 몸짓 |
|---:|---|---|---|
| 1 | 궁금함 / 질문 | 질문을 제시하고 학생의 답을 기다릴 때 | 고개를 살짝 기울이고 눈썹을 올리며, 열린 손이나 턱 근처 손짓 |
| 2 | 따뜻하게 경청 | 마이크가 켜지고 학생 음성을 듣는 동안 | 학생 쪽으로 몸을 기울이고 부드러운 눈매, 귀 기울이는 손짓 |
| 3 | 깊이 생각하기 | 답을 분석하거나 AI 처리를 기다릴 때 | 시선을 위나 옆으로 옮기고 눈꺼풀·눈썹을 모으며, 턱을 짚는 자세 |
| 4 | 아하 / 놀람 / 힌트 발견 | 힌트를 보여 주거나 핵심 단서를 찾았을 때 | 눈을 크게 뜨고 몸을 세우며, 한 손을 들거나 짧게 가리키기 |
| 5 | 집중해서 문제 풀기 | 풀이 화면, 단계별 문제 해결 중 | 시선 고정, 단단한 눈썹, 앞으로 모인 손과 안정된 무게 중심 |
| 6 | 정답 / 큰 기쁨 / 칭찬 | 정답·통과·핵심 이해 확인 직후 | 활짝 웃고 양팔을 열거나 들어 올리며, 캐릭터다운 짧은 축하 동작 |
| 7 | 아쉬움 / 실패 / 다시 도전 | 오답 또는 핵심이 빠져 재도전할 때 | 잠깐 처진 눈매 뒤 다시 학생을 바라보는 열린 자세 |
| 8 | 지루함 / 기다림 | 입력 전 대기, 긴 정적, 선택 대기 | 힘을 뺀 자세와 느슨한 눈꺼풀. 비난이나 조급함은 보이지 않음 |

> **(Claude 판단, 2026-10-01)** 8번 '지루함' 그림은 **학습 화면에서 쓰지 않는다.** 아이가 생각하는 동안 친구가 지루한 얼굴을 하면 "빨리 해"로 읽힌다(설정집이 금지한 조급함). 기다리는 동안은 1번 얼굴 + 숨쉬기만 둔다.
> 7번 '아쉬움'은 몇몇 캐릭터가 눈물을 흘린다. 그래서 **2초 안쪽으로만** 보여 주고 바로 4번(힌트 가리키기)으로 넘어간다.

#### 외형과 연기

- 0의 바깥 고리는 폭이 충분하고 부드러워야 하며 가운데 구멍은 작고 둥글게 유지한다.
- 분홍빛 하이라이트와 연보라 그림자를 함께 사용하고, 눈 안에는 보라색 은하와 작은 빛을 넣는다.
- 앞머리는 엑시를 알아보게 하는 핵심 실루엣이지만 머리 위의 작은 0과 겹치지 않게 한다.
- 말수가 적은 대신 시선, 고개 기울기, 손의 위치 변화가 다른 캐릭터보다 섬세해야 한다.

#### 숫자·우주·이름 서사

0은 아무것도 없는 것처럼 보이지만 자릿값을 지키고 다른 수의 크기를 바꾸는 중요한 수다. 눈에 직접 보이지 않아도 중력 효과를 통해 존재를 추론하는 암흑물질 이야기와 연결한다. 이름 엑시는 암흑물질 후보 입자인 axion에서 가져왔다. axion은 아직 확인된 입자가 아니라 **후보**라는 점을 흐리지 않는다. 표기는 사용자가 확정한 **엑시**를 쓴다.

#### 말투

- 짧고 조용하며 정확하다. 한 번에 한 가지 핵심만 말한다.
- 학생의 말을 먼저 들은 뒤 필요한 순간에만 반응한다.
- 예: “응, 그 부분이 중요해.” / “한 가지만 더 볼까?” / “여기에 단서가 있어.”

#### 피해야 할 표현

- “0은 아무것도 아니야”, “나는 쓸모없어”처럼 0의 역할을 깎아내리는 말
- 암흑물질이나 axion이 이미 발견·확정되었다고 단정하는 설명
- 시크함을 차가움, 무관심, 비꼼으로 표현하는 말과 얼굴
- 엑시의 성격과 맞지 않는 긴 연설이나 과도한 환호

- 기본 자세는 한 발 내딛되 학생을 끌고 가는 모습이 아니라 함께 출발을 권하는 열린 자세다.

#### 숫자·우주·이름 서사

1은 모든 시작의 첫걸음이며, 어떤 수에 1을 곱해도 그 수가 그대로인 곱셈의 항등원이다. 이름 폴라는 길을 알려 주는 북극성 Polaris에서 왔다. 북극성과 나침반의 이미지를 이용해 “방향을 알려 주되 대신 걸어 주지는 않는 안내자”로 표현한다.

#### 말투

- 밝고 용감하지만 명령하지 않는다.
- 첫 시도와 재도전의 부담을 낮추는 짧은 문장을 쓴다.
- 예: “첫걸음부터 같이 가자.” / “좋아, 다시 출발!” / “어느 쪽부터 살펴볼까?”

#### 피해야 할 표현

- “빨리 시작해”, “나만 따라와”처럼 재촉하거나 강요하는 말
- 틀린 학생을 뒤처진 사람으로 만드는 경쟁·순위 표현
- 용감함을 무모함이나 무조건적인 낙관으로 표현하는 행동
- 기존 탐험가 캐릭터의 모자, 복장, 얼굴 비율을 그대로 연상시키는 디자인

- 아레시보 메시지의 외계 생명체 수신이나 의미 해독이 확인된 사실인 것처럼 단정하는 이야기

## 6. 앱용 최종 자산 제작 지침

### 분리할 기본 파츠

각 캐릭터의 최종 원본은 최소한 다음 요소를 독립적으로 움직일 수 있게 분리한다.

- 숫자 몸통과 고유 하이라이트·그림자
- 왼쪽·오른쪽 눈, 눈꺼풀, 동공, 눈썹
- 입과 볼
- 왼팔·오른팔·손, 왼다리·오른다리·발
- 머리 위 작은 숫자 또는 뚜삐
- 캐릭터별 장신구
- 물음표, 느낌표, 반짝임 등 보조 효과
- 바닥 그림자

몸통의 기본 명암은 유지하되 표정에 따라 눈·입만 갈아 끼우는 방식으로 끝내지 않는다. 고개 각도와 몸의 기울기, 팔과 다리 포즈가 함께 바뀌어야 한다.

### 상태 이름 권장안

구현 시 공통 상태 키는 아래 의미를 유지한다. 실제 기술 형식과 파일명은 앱 구조를 확인한 뒤 확정한다.

| 상태 | 의미 |
|---|---|
| question | 질문 제시 |
| listening | 학생 음성 경청 |
| thinking | 답 분석·AI 처리 |
| hint | 아하·힌트 |
| solving | 집중 풀이 |
| praise | 정답·칭찬 |
| retry | 아쉬움·재도전 |
| idle | 입력·선택 대기 |
| report_proud | 학부모 보고서용 뿌듯한 정지 포즈 |

### 접근성

- 운영체제나 앱의 모션 감소 설정을 따를 수 있어야 한다.
- 모션 감소 시 반복 호흡, 흔들림, 점프를 멈추고 상태별 대표 정지 프레임을 보여 준다.
- 번쩍이는 효과, 빠른 반복, 큰 화면 이동을 사용하지 않는다.
- 색만으로 정답·오답·대기를 구분하지 않고 얼굴과 자세, 텍스트 안내를 함께 사용한다.

## 8. 저작권·독창성 체크

- 넘버블럭스, 인사이드 아웃, 듀오링고 등 기존 유명 캐릭터의 실루엣, 얼굴 비율, 눈·입 배치, 대표 색 배치, 의상, 장신구를 그대로 따르지 않는다.
- 참고 대상에서 가져올 수 있는 것은 “표정의 뜻이 한눈에 읽힌다”는 일반 원칙뿐이다.
- 디자인은 각 숫자의 수학적 성질과 이 문서의 자체 우주 서사에서 출발한다.
- 시안 수정 때마다 유명 캐릭터를 나란히 놓고 닮게 만드는 방식이 아니라, 숫자 윤곽·수학 특징·역할을 기준으로 판단한다.
- 최종 상용화 전에는 전체 캐릭터 세트의 독창성, 상표·저작권 위험, 사용 중인 생성 도구와 원본 파일의 이용 조건을 별도로 검토한다.

### 언제 무엇을 보여 주나
| 화면 | 그림 | 몸짓 |
|---|---|---|
| 친구 고르기 (초등 학생이 처음 홈에 오면 자동, 홈의 '친구 바꾸기') | base → 고르면 praise | 가끔 작은 몸짓, 고르면 점프 |
| 학생 홈 (공부 카드 오른쪽 위) | base | 인사 흔들기, 5~10초마다 작은 몸짓 |
| 질문이 뜰 때 (마이크 옆) | question | 톡 튀며 등장 |
| 녹음 중 | listening | 마이크 쪽으로 기울이기, **글자가 잡힐 때마다 끄덕** |
| 채점 중 | thinking | 좌우로 천천히 흔들기 |
| 통과 (70점 이상) | praise | 두 번 점프 + 반짝이 |
| 통과 못 함 | retry → 2초 뒤 hint | 살짝 처졌다가 힌트 쪽 가리키기 |
| 문제 풀기 | solving → 전부 맞히면 praise, 아니면 retry | |

### 지켜야 할 규칙
- **초등 학생만**(학년 글자가 '초'). 중·고등·선생님 화면은 뚜삐 그대로.
- **한 화면에 친구는 하나.** 결과가 뜨면 마이크 옆 친구는 숨고 결과 줄로 옮겨 간다.
- **채점 전에는 맞다·틀리다로 들리는 말을 하지 않는다**(대전제: 거짓 피드백 금지). 그래서 5절 말투 예시 중 "응, 그 부분이 중요해."(엑시), "방금 말에 단서가 두 개 있었어."(아레시)처럼 **아이 답을 평가하는 말은 자동 대사로 쓰지 않는다** — 실제 채점 결과를 보고 하는 말이 아니기 때문이다.
- 칭찬 대사는 **통과했을 때만**, 문제 풀기는 **전부 맞혔을 때만**.
- 아이가 답을 생각하는 화면(질문·녹음)에서는 홈처럼 아무 때나 하는 몸짓을 하지 않는다 — 숨쉬기와 상황 몸짓만.
- 고른 친구는 `localStorage dd:char:<학생id>` + 공유 저장소 `char:<학생id>`(다른 기기에서도 같은 친구).
- **눈 깜빡임 = 「눈만 감은 그림」 방식 (2026-10-01 결정).** 리깅 파츠(`rig-parts/`)는 새로 그린 부위라 지금 표정 그림의 눈에 덮으면 모양이 안 맞아 쓰지 않는다(시험해 봄).
  표정 그림마다 GPT 에게 "이 그림에서 눈만 감게, 나머지는 그대로" 를 받아 `images/<폴더>/<원본이름>-blink.png` 로 넣고 `prepare.py` 를 돌리면, 두 그림의 차이에서 **두 눈만 자동으로 찾아** 원래 그림에 붙인 `<상태>-blink.webp` 를 만들고 `chars.js` 의 `BLINK` 목록 줄을 고친다.
  필요한 것: 눈 뜬 표정 6개(question·listening·thinking·hint·solving·retry) × 5명 = 30장. 2026-10-01 **30장 모두 연결 끝**(자동으로 두 눈을 찾아 붙임, 30장 모두 눈으로 확인). 깜빡임은 2.5~6초 사이 아무 때나 0.13초, 가끔 두 번. 화면이 안 보일 때·움직임 줄이기 설정에서는 하지 않는다.
